# Instruções permanentes — BI Factory SEPPE

**Primeiro passo obrigatório:** ler `docs/ESTADO_ATUAL.md` e `docs/DIARIO_TECNICO.md`, depois verificar o código e o estado do Git antes de alterar o projeto.

- Repositório: `edineilemes-source/bi-factory-seppe`. Branch de trabalho conhecida: `feat/unificar-8504-8510` (confirmar).
- Não presumir que GitHub e Codespaces estejam sincronizados. Não afirmar acesso ao terminal do Codespaces quando só há acesso ao GitHub.
- Priorizar o estado efetivo do código, dos dados e dos testes sobre a memória de conversas.
- Preservar todos os dados, arquivos não rastreados, produtos e layouts. Não executar operações destrutivas.
- Antes de commit, push, merge, rebase ou reset, avisar e verificar riscos; não realizar silenciosamente.
- Usar somente dependências Open Source com licença identificada.
- Não substituir ECharts nem reescrever módulos funcionais sem justificativa e aprovação.
- Agrupar diagnósticos/testes em uma bateria; informar resultados consolidados, sem solicitar uma sequência de comandos individuais.
- Toda entrega deve atualizar `docs/ESTADO_ATUAL.md` e acrescentar entrada em `docs/DIARIO_TECNICO.md` com fatos confirmados, pendências, testes e SHA.
- Não armazenar segredos, credenciais, tokens, dados pessoais ou dumps de produção na documentação versionada.
